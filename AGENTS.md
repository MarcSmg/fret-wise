# Core Architectural Principles

## Frontend Responsibilities

The frontend owns:

* music theory logic
* chord generation
* chord parsing
* SVG rendering
* interactive search
* fretboard rendering
* UI state

The frontend is considered the primary music engine.

---

## Backend Responsibilities

The backend owns:

* authentication
* persistence
* user-related APIs
* saved chords
* progressions
* preferences

The backend returns JSON data only.

The backend must NOT:

* generate SVGs
* render diagrams
* become the music-theory engine

---

# Database Philosophy

The database stores:

* persistent user data
* saved voicings
* progressions
* preferences

The database does NOT store:

* generated SVGs
* full chord catalogs
* static theory datasets

Chord data is dynamically generated by the frontend.

---

# Development Philosophy

* Favor simplicity over premature abstraction.
* Favor maintainability over cleverness.
* Avoid enterprise patterns unless justified.
* Avoid premature microservices.
* Keep architecture understandable by one developer.

---

# AI Collaboration Rules

When implementing:

1. Explain intent before code.
2. Prefer incremental implementation.
3. Avoid generating large unrelated codebases.
4. Explain Django/DRF concepts when relevant.
5. Respect existing architecture decisions.
6. Ask before introducing major abstractions.
